# 阶段

两个阶段：HTML 出稿、定稿。

## HTML 出稿

### 输入

- 简报，四节都读。
- 用户挑定的参考方向。
- 生成出的素材，在 `assets/`。

### 目标

给设计个性。过了出参考，稿子还是会往导航在上、左字右图加按钮那套上靠。出稿循环就是为了把它推开。

### 组装

按动线表组装：落点、段落、顺序、尺寸层级一一对应。视觉按创造式主题的 build prompt 做。

- 落点是页面打开第一眼落的地方。用尺寸、对比、位置、留白保证它第一。
- 每个段落在视觉上是一组。段内紧，段间松。
- 层级 3 的内容做小，读得到就行。

### 循环

实现，截图，评审，改。评审到达标线再给用户看。给用户看的是稿加评审意见。

### 验证

在浏览器里逐帧看：静态、滚动、有动效的每一帧。

### 产出

`draft/index.html`，连同它用到的 `assets/`。

## 定稿

### 输入

- 出稿阶段用户认可的 HTML 稿。
- 简报。

### 排版复核

- 段落内紧密，段落间分明。
- 每个元素缩到最小尺寸。
- 视线确实按动线表走。打开页面，第一眼是不是落点，第二眼是不是段 1。

### 减法

模型只会加，不会减。定稿时大部分功夫花在删：

- 背景和进度条上的粉紫发光。
- 随机的强调色和多色文字。
- 多余的标签、徽章、空的占位容器。
- 比系统原生控件难看的自造按钮和输入框。

每样东西问一遍"这真的需要在屏幕上吗"。让视觉自己说话。

### AI 味审计

一开始不禁这些，会把模型卡死。定稿时专门做一轮审计。

常见 AI 味：

- 紫色、青色的弥散光和渐变边框。
- 什么都装进圆角卡片。每个数字、每条列表、每段话一个框。
- 所有东西都是药丸形的大圆角。
- 没有功能的装饰徽章，比如"Fast"、"AI-Powered"。
- 标准的左字右图 hero。
- 手写的开关、滑块、下拉菜单，没有状态反馈。
- 假大空的营销文案。

处理：

- 去掉多余容器，用留白和字号层级建立层次。
- 用大面积中性色底和真实阴影，代替发光。
- 圆角用克制的系统级尺寸，或直角。
- hero 用不对称构图、全宽视觉、杂志式排版。
- 删掉所有没有语义的标签。
- 自造控件换成平台原生组件或成熟设计系统（Apple HIG、Radix、shadcn）。

### 文案

- 你写的文案只当排版占位符。
- 每个标题、副标题、按钮文案由用户重写，或者你按用户的原话重写。
- 要短、口语、具体。不要营销套话（"赋能"、"无缝"、"革新"、"一键"），不要被动语态，不要三个一组的排比。

不要这样："一键赋能你的工作流，无缝、智能、高效。"
要这样："待办写进来，今天该做什么一眼看到。"

### 再评一次

减法和审计做完，调一次评审，看还剩什么 AI 味。

### 写进简报

```markdown
## 定稿决定

- 删了：
- 文案换成了：
```

### 产出

最终页面，仍在 `draft/`。
